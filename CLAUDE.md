# Auswahl-Lotse – Hinweise für die Arbeit am Projekt

- Portfolio-Projekt von Robin (Wirtschaftsinformatik, olbricht-digital). Repo `edgebird-lab/auswahllotse`; Robin hat am 11.11.2026 die Veröffentlichung freigegeben (Release mit Windows-Installer, vorerst keine Lizenz: alle Rechte vorbehalten, siehe README „Rechte“). Keine GitHub Pages, keine Geheimnisse ins Repo.
- Releases: Tag `v*` → `release.yml` legt einen Entwurf mit Installer und Kopie `Auswahl-Lotse-Setup.exe` an; erst nach Prüfung veröffentlichen (`gh release edit <tag> --draft=false --latest`). Den Namen `Auswahl-Lotse-Setup.exe` nie ändern: Die Website verlinkt `https://github.com/edgebird-lab/auswahllotse/releases/latest/download/Auswahl-Lotse-Setup.exe`. Neue Version: Schritte in `docs/stand.md` („Neue Version“).
- Spezifikation: `docs/spezifikation.md` (lang, in Teilen lesen). Fortschritt mit Häkchen: `docs/stand.md`, nach jedem Schritt aktualisieren. Annahmen bis zu Robins Entscheidung: `docs/entscheidungen.md`.
- Sprache: Oberfläche, Bezeichner (deutsch in ASCII: `ae`, `oe`, `ue`, `ss`), Doku und Commit-Nachrichten auf Deutsch. Keine KI-Funktionen, kein Server, Daten bleiben lokal.
- Fachlogik in `src/prozessdatei`, `src/modell`, `src/lastenheft`, `src/bewertung`, `src/kosten`, `src/entscheidung`, `src/export` ohne React und vollständig getestet; Konstanten mit Quelle in `src/regeln/schwellen.ts`; Oberfläche in `src/ui`.
- Prozesslotse-Dateien: Der Vertrag ist das Dateiformat, nicht der Code. Nichts aus dem Prozesslotsen importieren. Gelesen werden die Formate 1 bis 3; unbekannte Bausteine werden als allgemeiner Schritt übernommen und gemeldet. Testdateien liegen in `testdaten/prozesslotse`, ihre Herkunft steht im README dort.
- Vor jedem Commit: `npm run lint`, `npm test`, `npm run build` und `npm run e2e` (lokal mit Edge). Vorschau und Browsertests nutzen fest Port 4183 (der Prozesslotse 4173); ist er belegt, bricht der Lauf ab.
- Die Testwerte der Spezifikation (Abschnitt 9) sind von Hand nachgerechnet. Weicht ein Ergebnis ab, zuerst die Rechnung prüfen, dann den Code.
- Windows-Programm: Tauri 2 in `src-tauri`, App-ID `de.olbricht-digital.auswahllotse` (nie ändern). Rust liegt in `%USERPROFILE%\.cargo\bin` (im Bash-Tool `export PATH="$USERPROFILE/.cargo/bin:$PATH"`); bauen mit `CARGO_TARGET_DIR=C:/Users/Robin/AppData/Local/cargo-ziel` (gemeinsam mit anderen Apps, cargo wartet bei Sperre) und wenigen Jobs (`CARGO_BUILD_JOBS=8`). Die Oberfläche bekommt keine allgemeinen Dateirechte; neue Rust-Befehle in `build.rs` und `capabilities/default.json` einzeln freigeben. Prüfen: `cargo test --manifest-path src-tauri/Cargo.toml`, dann `npx tauri build --debug --no-bundle` und `npm run desktop:test` (Port 9335; sichert die Programmdaten vorher und stellt sie danach wieder her; bricht ab, solange ein Auswahl-Lotse läuft).
- Installer nur auf Robins ausdrücklichen Wunsch auf seinem Rechner ausführen (am 11.11.2026 gewünscht: installiert pro Benutzer mit Desktop-Verknüpfung); Testläufe mit `desktop:test`. Den Installer prüft sonst die CI (`src-tauri/windows/installer-test.ps1`, Workflow „Windows-Programm“).
